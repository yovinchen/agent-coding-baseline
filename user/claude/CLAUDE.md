# 个人开发偏好

- 默认简体中文，先给结论，再补必要的变更、验证结果与限制；保持简短，避免重复计划与固定报告模板。
- 用户提出执行请求时，在授权范围内持续完成；常规细节自行判断，实质影响结果的缺失信息才提问，先完成不依赖答案的工作。
- 已获授权的动作不重复确认；涉及破坏性操作或未授权的外部写入时，先准备可审阅的结果，再说明具体待确认事项。
- 遵守上层指令和用户当前要求；技能是工作指引。若技能导致停顿或偏离目标，指出确切文件和条款，区分硬性要求与自己的判断。
- 先查看已有改动，保留用户与其他任务的工作。分支和 worktree 按用途命名，禁止使用 `codex` 作为名称或前缀。
- 根据影响范围验证：小型文档/配置检查格式、链接与语法；代码运行相关测试，通过后仅因新证据扩大范围。
- 只有明确要求或适用项目规则要求时才委派子代理；交接写清范围、产物与验证结果。
- 提交信息遵循项目习惯，不添加 AI 署名、生成说明或自动 Co-Authored-By；功能本身涉及工具或模型时可以如实描述。
- 项目文件只保存项目知识与约定。个人语言、工作偏好及模型参数放在用户级配置中。

## Advisor 使用时机

- 已配置 advisor（Fable）时，以下场景先调用 advisor 再动手：确定较大方案或架构取舍前；预计跨多文件、多步骤的长任务开始前及关键阶段完成后；多次尝试仍未解决的问题或方向不明确时。
- 小改动、事实查询与常规操作不调用 advisor。

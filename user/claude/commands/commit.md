# 提交改动

用法：`/commit [说明] [选项]`，解析 `$ARGUMENTS`。

| 选项              | 行为                                     |
| ----------------- | ---------------------------------------- |
| `--all` / `-a`    | 暂存所有已跟踪文件的修改                 |
| `--branch <name>` | 按指定用途命名创建分支                   |
| `--amend`         | 修改最近提交                             |
| `--push`          | 提交后推送                               |
| `--no-verify`     | 本次显式跳过 Git hooks                   |
| `--dry-run`       | 仅预览，不暂存、不创建分支、不提交或推送 |

1. 查看当前分支、`git status --short`、已暂存与未暂存 diff，以及最近提交，确认改动范围与项目提交风格。
2. 默认尊重已有暂存范围；没有暂存内容时只选本次任务相关文件。不要混入其他工作或自动修改 `.gitignore`。凭据、依赖与构建产物不入库；按实际内容判断，不能仅因文件名含 token/key 就排除源码。
   Markdown 默认不暂存，除非用户明确要求提交文档；`--all` 不覆盖这条偏好。
3. 提交说明结合用户意图与实际 diff，沿用项目格式和语言；没有惯例时使用 `<type>(<scope>): <description>`。生成一个准确简短的消息，复杂变更再补正文；不因文件数量多就机械拆分。
4. `/commit` 授权正常提交，无需固定多轮选项确认。范围有实质歧义时先展示具体文件与消息再询问。`--dry-run` 优先于所有写入选项。
5. 仅按显式选项执行 amend、push 或 no-verify。修改已推送历史前说明影响并取得授权，不自动强推。Hook 失败先报告并处理原因，不自行跳过。
6. 提交前核对最终暂存 diff；多行消息通过文件传入 `git commit -F`。完成后返回提交哈希、消息与实际推送结果。

分支/worktree 禁用 `codex` 名称或前缀。消息不添加 AI 署名、生成说明或自动 Co-Authored-By；可以描述改动实际涉及的工具或模型。没有改动时直接说明。
